修掉的缺陷（3 个，全部本步实测发现）
--------------------------------------------------------------------------------
D1[P1·构建] Cargo.toml tauri features 缺 app-all，与 tauri.conf.json allowlist(app.all)
    不匹配 → tauri-build 自定义构建脚本直接失败。修复=features 增补 "app-all"。

D2[P0·运行级致命] T-WIN app.js 顶层重复声明 BleUtils.js 的顶层名
    （const MAX_RECONNECT_ATTEMPTS + function escapeHtml）→ 浏览器在脚本实例化期抛
    "Identifier 'MAX_RECONNECT_ATTEMPTS' has already been declared" → 整个 app.js
    不执行 → T-WIN 前端逻辑（Tab 切换/扫描/重连/Smart HID 全部）从未运行过，
    页面只是 index.html 静态壳（默认 Tab 高亮 + 占位文案）。Rust 工具链此前未解锁、
    无运行级验证，故一直未暴露。
    定位链：CDP 走查函数全 undefined → 资源时序证明 app.js 已加载执行 →
    addScriptToEvaluateOnNewDocument 预埋错误陷阱 → 重载抓到实例化期 SyntaxError。
    修复=删除 app.js 两处重复声明（escapeHtml 调用数=0，纯死代码；MAX_RECONNECT_
    ATTEMPTS 引用改用 BleUtils 顶层常量，经典脚本共享全局词法环境）。
    防回归=新增 tests/desktop/script-co-load.test.mjs（7 例）：把两线 index.html
    脚本链按真实顺序装入同一 vm 上下文（vm 全局词法环境跨脚本持久，重复顶层声明
    与浏览器同语义抛错）。反证已做：把重复声明注回 → 门禁立即以同款错误失败。

D3[P2·显示] P002 连接失败横幅的协议码片是静态占位 identity_failed（两线同病），
    渲染只填文本不更新码片 → 任何传输级错误（如 Device not found）都顶着
    identity_failed 假码。修复=码片加 id hidProvConnErrorCode，渲染按 error.code
    填充、无协议码则隐藏（E-WIN/T-WIN 双线镜像修；E-WIN 为 CRLF、T-WIN 为 LF，
    补丁按各自行尾口径）。

方法与坑（复现要点）
--------------------------------------------------------------------------------
- WebView2 CDP：WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9444
  启动 exe → http://127.0.0.1:9444/json 取 page target → node 23.8 WebSocket
  Runtime.evaluate（与 Electron 冒烟同一套驱动）。
- Page.reload 会摧毁在途 Runtime.evaluate 上下文（"Execution context was destroyed"），
  走查期间勿并发 reload。
- Cargo.toml 是 LF、E-WIN app.js 是 CRLF、T-WIN app.js 是 LF——跨线补丁必须先探行尾。
- ~/.cargo/bin 不在 Git Bash 默认 PATH，cargo 命令需 export PATH 前置。
