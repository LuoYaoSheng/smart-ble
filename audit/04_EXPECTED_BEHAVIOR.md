# 期望产品行为

## F002 连续扫描

- 用户：U01/U02；入口：各自页面明确的“开始扫描”。
- 合理流程：检查蓝牙/必要权限一次 → 创建带 ID 的 scan session → 显示开始时间与进度 → 流式更新 → 用户停止、超时或页面隐藏 → 确认停止并 flush → 可立即再扫。
- 成功：显示本轮结果与计数；零设备是正常的空结果。
- 失败：显示 API 错误类别、操作建议与“重试”；不能把失败伪装成零设备。
- 真机：必须 E4；开发者工具只能辅助。

## F003 广播 Snapshot

- 应保留并展示名称、RSSI、service UUID、raw advertise data、service data、manufacturer data；分别显示“未提供/空/已解析”。
- 不能声称一定读到所有广播字节：OS、权限和外设广播配置会限制可见字段。

## F006 Smart HID 配网

- 弱匹配仅展示“可能是”；连接后必须由 service UUID + Device Info 确认。
- 写入前已订阅结果；配网错误按 V1 稳定错误码给到精准恢复动作；密码/token 不展示、不日志、不持久化。
- 完成页说“已收到 ready 状态”，而非未经验证地声明 USB HID 已工作。

## F008 历史设备诊断

- 历史记录不应直接显示在线；点击诊断后应用用 deviceId 重新扫描/连接/验证，或明确告诉用户需要回到配网向导连接。

## F010 静态图片

- 任一页面引用的 `/static/...` 必须在微信 dist 中存在；加载失败有占位/文本，不出现空白。

## F011 分享

- 当前只是工具品牌分享，不需要海报或业务 scene 回流；应提供一致的标题、路径和已验证的图片。若没有传播目标，分享入口应降级为次要入口。
