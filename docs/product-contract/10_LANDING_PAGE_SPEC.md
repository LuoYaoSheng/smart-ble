# Smart BLE 公开落地页规范

## 目标

落地页是开源项目的统一入口，帮助访问者在一分钟内回答：

1. BLE Toolkit+ 是什么？（多平台多框架的开源 BLE 工具家族）
2. 当前哪个版本真正可用？
3. 能做哪些 BLE 操作？
4. 如何用 ESP32 从零复现？
5. 去哪里体验、下载、读文档和参与贡献？

落地页不展示内部审计与未验证完成度；多平台实现家族按统一产品规范如实呈现，不把在研实现线伪装成已发布，也不使用「多端大一统」「全平台统一下载」类定位。

## 信息架构

### 1. 顶部导航

- 功能（/#features）

- GitHub（socialLinks）

### 2. Hero

- 产品名：BLE Toolkit+（对外统一名；仓库内部名 smart-ble）
- 一句话：多平台多框架的开源 BLE 工具家族——微信小程序、Android、iOS / macOS 原生、桌面与 ESP32 固件，收进同一条调试工作流
- 主行动：微信扫码使用（真实小程序码，D8 主推口径）
- 次行动：查看文档 / GitHub
- 工作流口径：扫描、连接、读写、订阅、广播与 ESP32 验证，收进同一条工作流

### 3. 核心闭环

用一条简洁流程展示：

```text
发现设备 → 检查广播 → 连接 → GATT 读写/Notify → 日志 → 广播/OTA → ESP32 验证
```

### 4. 当前能力

展示经过测试的能力卡：扫描、筛选、连接、多设备、Read/Write/Notify、广播、OTA、Profile、Smart HID。每张卡链接到对应功能编号或教程。

### 5. 平台状态

落地页以「多平台多框架，一个工具家族」呈现实现家族全景，每卡链接对应构建教程；发布状态用词与 `08_RELEASE_GATES.md`/状态页一致，不弱化：

| 实现线 | 框架 / 技术 | 落地页定位 |
|---|---|---|
| 微信小程序 | UniApp（Vue）一线 | 扫码即用 · 开发预览（主推入口，真实小程序码 + 扫码文字等价） |
| Android | UniApp 一线 + 原生 Kotlin（apps/android） | 客户端主线 · 开发预览 |
| iOS / macOS | SwiftUI + CoreBluetooth，共享 SmartHidCore（apps/ios） | 原生线 · 源码可构建 |
| Flutter | Android / macOS（apps/flutter） | 跨框架 · 源码可构建 |
| 桌面 | Tauri / Electron / macOS Native（apps/desktop） | 桌面线 · 源码可构建 |
| H5 | UniApp 一线 | 降级体验 · 无真实 BLE（明确标注不支持） |
| Web | 本站（VitePress）+ HTML 交互原型 | 原型 · 可交互 |
| ESP32 固件 | ESP-IDF（hardware/） | 硬件夹具 · 开发中 |

脚注必须诚实声明：各实现线当前均未发布正式产物；微信小程序可扫码体验，其余平台可从源码构建；能力与发布状态以状态页与 `05_PLATFORM_MATRIX.md` 为准。

## 实现约束

- 使用现有 VitePress `docs/index.md` 和品牌资产演进，不新建第二套官网技术栈。
- 页面数据优先来自产品契约/构建时元数据，避免手工复制平台状态。
- 响应式覆盖手机和桌面；核心内容无 JavaScript 也能阅读。
- 图片有 alt，导航键盘可达，对比度和焦点可见。
- 下载、二维码、外部链接必须在每次发布后自动或人工验证。

## 不展示的内容

- 内部 P0/P1 审计过程和重复旧文档列表
- 未通过真机却标记“完整支持”的平台
- 不可下载的占位按钮
- 历史产品名混用
- 私有 Smart HID token、内部 ControlHub 地址或测试账号

- 首屏能识别产品、当前主版本和三个主要入口。
- 从落地页最多两次点击到达微信、Android、ESP32、原型和贡献指南。
- 平台状态与 `05_PLATFORM_MATRIX.md` 一致。
- 能力声明与 `08_RELEASE_GATES.md` 的证据一致。
- 手机、桌面、暗色/亮色和无障碍基本检查通过。
