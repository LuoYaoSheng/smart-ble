# Smart BLE 公开落地页规范

## 目标

落地页是开源项目的统一入口，帮助访问者在一分钟内回答：

1. Smart BLE 是什么？
2. 当前哪个版本真正可用？
3. 能做哪些 BLE 操作？
4. 如何用 ESP32 从零复现？
5. 去哪里体验、下载、读文档和参与贡献？

落地页不直接展示内部审计、未验证完成度或多个互相竞争的实现入口。

## 信息架构

### 1. 顶部导航

- Smart BLE
- 在线原型
- 快速开始
- ESP32
- 平台状态
- 文档
- GitHub

### 2. Hero

- 产品名：Smart BLE
- 一句话：开源的跨平台 BLE 调试、学习与硬件联动工具
- 主行动：体验 UniApp / 查看交互原型
- 次行动：用 ESP32 开始 / 查看源码
- 显示当前正式目标：Android App + 微信小程序

### 3. 核心闭环

用一条简洁流程展示：

```text
发现设备 → 检查广播 → 连接 → GATT 读写/Notify → 日志 → 广播/OTA → ESP32 验证
```

### 4. 当前能力

展示经过测试的能力卡：扫描、筛选、连接、多设备、Read/Write/Notify、广播、OTA、Profile、Smart HID。每张卡链接到对应功能编号或教程。

### 5. 平台状态

| 平台 | 公开状态 |
|---|---|
| UniApp Android App | 当前完整版本目标；发布后显示版本与证据 |
| 微信小程序 | 当前正式入口；注明微信平台限制 |
| UniApp iOS App | 规划中/验收中，不提前宣称完整 |
| H5 | 文档与降级体验，不支持真实 BLE |
| 其他客户端 | 参考实现，首版完成后再整理 |

### 7. 交互原型

嵌入或链接 HTML 原型，说明可切换微信、Android、iOS、H5，查看正常、空、失败、断线和不支持状态。

分为三条 5 分钟路径：

- 我只想体验微信小程序
- 我要安装 Android App
- 我要刷 ESP32 并完成第一次联调

## 实现约束

- 使用现有 VitePress `docs/index.md` 和品牌资产演进，不新建第二套官网技术栈。
- 页面数据优先来自产品契约/构建时元数据，避免手工复制平台状态。
- 响应式覆盖手机和桌面；核心内容无 JavaScript 也能阅读。
- 图片有 alt，导航键盘可达，对比度和焦点可见。
- 下载、二维码、外部链接必须在每次发布后自动或人工验证。

## 不展示的内容

- 内部 P0/P1 审计过程和重复旧文档列表
- 未通过真机却标记“完整支持”的平台
- 不可下载的占位按钮
- 历史产品名混用
- 私有 Smart HID token、内部 ControlHub 地址或测试账号

## 验收

- 首屏能识别产品、当前主版本和三个主要入口。
- 从落地页最多两次点击到达微信、Android、ESP32、原型和贡献指南。
- 平台状态与 `05_PLATFORM_MATRIX.md` 一致。
- 能力声明与 `08_RELEASE_GATES.md` 的证据一致。
- 手机、桌面、暗色/亮色和无障碍基本检查通过。
