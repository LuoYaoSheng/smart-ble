# UniApp 与 ESP32 测试矩阵

## 证据等级

| 等级 | 证据 | 能证明什么 |
|---|---|---|
| E0 | 文档/静态检查 | 配置、路由、UUID、资源存在 |
| E1 | 单元测试 | 纯逻辑、状态机、编解码 |
| E2 | Fake integration | Runtime 调用顺序、超时、并发、清理 |
| E3 | 构建 | Android/微信/H5 编译通过 |
| E4 | 模拟器/页面自动化 | 页面、状态、跳转和视觉基本可达 |
| E5 | 真机 + ESP32/观察端 | BLE、权限、射频、插件、OTA 真实结果 |

Must 硬件功能必须达到 E5；页面和纯逻辑功能至少达到 E4/E2。

## 结果判定

- `PASS`：操作、设备结果、客户端反馈和后续状态全部符合。
- `FAIL`：任一层不符，记录第一个断点和后续影响。
- `BLOCKED`：缺硬件、权限或外部依赖；不能记为 PASS。
- `N/A`：平台明确不支持且已按矩阵降级。

任何 FAIL 都要附：复现步骤、平台、commit、ESP32 版本、日志/截图、第一断点和回归用例 ID。
