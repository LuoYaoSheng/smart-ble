# UniApp 第一完整版本产品范围

## 产品目标

Smart BLE 是一个开源 BLE 调试、学习和硬件联动工具。第一个完整版本以 UniApp 实现为参考产品，让用户能够从发现设备开始，完成连接、GATT 调试、日志排查、广播、OTA 和第一方设备 Profile 任务，并使用 ESP32 参考设备复现全部核心链路。

多个平台最终完成同一个目标，但平台布局、权限、后台能力和 Peripheral 支持允许不同。当前先完成 UniApp，不并行改造其他客户端。

## 目标用户

- BLE 固件与硬件开发者
- Android、iOS、微信小程序开发者
- 需要现场排查 GATT 协议的测试和技术支持人员
- 学习 BLE 扫描、连接、读写、Notify、广播和 OTA 的开发者
- 需要接入第一方设备 Profile 的开源贡献者

## 第一阶段发布目标

| 目标 | 定位 | 完成标准 |
|---|---|---|
| UniApp Android App | 首个完整运行时 | Core BLE、ESP32、广播、OTA、页面和异常链路通过真机 |
| 微信小程序 | 微信生态正式入口 | 完成微信允许的 Core BLE、页面、Smart HID 和 Peripheral 能力 |
| ESP32 LightBLE | 标准测试夹具 | 协议、权限组合、通知、LED、OTA 和故障用例可重复 |
| HTML 交互原型 | 产品和交互母版 | Android/微信/iOS/H5 模式可切换，所有页面和状态可点击 |
| 公开落地页 | 开源项目入口 | 准确展示定位、能力、平台状态、硬件、文档和下载入口 |

## 后续但不阻塞第一阶段

- UniApp iOS App 按相同 Core 契约补齐真机证据。
- Flutter、原生 Android/iOS、Tauri、Electron 等客户端只读取本契约，不在当前阶段同步实现。
- H5 保持页面可访问和能力说明，不宣称支持 Web BLE。

## 核心产品原则

1. **通用 BLE 优先**：移除任一 Profile 后，扫描、连接、GATT、日志和广播仍可使用。
2. **功能语义统一**：页面布局可以不同，操作含义、状态和成功标准不能漂移。
3. **能力诚实**：平台不支持时展示原因与替代路径，不显示无效按钮或假成功。
4. **硬件可复现**：每个 Must 功能必须能用 ESP32 参考固件或明确的第二设备复现。
5. **错误可恢复**：权限拒绝、超时、断线、错误指令和失败升级均必须给出下一步。
6. **开源可贡献**：协议、功能、测试步骤、证据格式和新增 Profile 流程均公开。

## 非目标

- 第一阶段不同时重构所有历史客户端。
- 不把 HTML 原型当成生产运行时。
- 不以模拟器截图替代 BLE 真机证据。
- 不为追求跨平台外观一致而违背平台导航和权限规范。
- 不在通用 BLE 层写死 Smart HID 或特定私有设备业务。

## 第一版本成功标准

- Android App 和微信小程序能用同一 ESP32 固件完成各自支持的 Must 流程。
- 10 个 UniApp 页面与 HTML 原型一一对应，操作、状态、跳转和文案有稳定编号。
- 所有 Must 功能拥有自动化或真机证据；需要硬件的项目至少有 Android 和微信证据。
- 落地页只展示已验证能力，并明确平台差异和实验状态。
- 新开发者按照文档能在 30 分钟内刷入 ESP32 固件并完成首次扫描、连接、写入和 Notify。
