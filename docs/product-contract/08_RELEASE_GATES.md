# 发布门禁

## Gate 0：产品契约

- [ ] 功能目录、流程、页面和平台矩阵编号一致。
- [ ] HTML 原型覆盖 10 页和关键状态。
- [ ] Android、微信、iOS、H5 差异有明确支持/降级结论。
- [ ] ESP32 协议与测试固件版本已冻结。

## Gate 1：静态与自动化

- [ ] `./scripts/verify-uniapp.sh` 全部通过。
- [ ] `./scripts/verify-uniapp-pages.sh` 全部通过。
- [ ] Android App、微信小程序和 H5 生产构建通过。
- [ ] 协议锁、资源、SFC、路由、页面契约无漂移。
- [ ] ESP32 `pio run` 和固件自动测试通过。

## Gate 2：Android 真机

- [ ] TEST-A-001~014 完成。
- [ ] 至少一台 Android 12+ 和一台低版本/不同厂商设备完成核心回归。
- [ ] ESP32 主服务、权限服务、Notify、故障注入和 OTA 有双端证据。
- [ ] 无 P0/P1；P2 有明确发布决策。

## Gate 3：微信真机

- [ ] TEST-W-001~010 完成。
- [ ] 使用稳定微信基础库和正式 AppID。
- [ ] 扫描、连接、GATT、central/peripheral 切换由真实设备证明。
- [ ] Smart HID 正常流程及关键错误恢复有证据。
- [ ] 分享、外链和小程序跳转按正式配置验证。

## Gate 4：开源交付

- [ ] 落地页的平台声明与测试结果一致。
- [ ] README 可在 5 分钟内找到体验、文档、ESP32 和贡献入口。
- [ ] ESP32 刷写教程在新电脑上从零复现。
- [ ] 发布包含版本、commit、APK/小程序版本、固件版本和已知限制。
- [ ] 测试证据不包含 Wi-Fi 密码、token、设备隐私或开发者密钥。

## Gate 5：发布后回归

- [ ] GitHub/Gitee Release 资源可下载。
- [ ] 落地页链接、二维码和文档无断链。
- [ ] 新安装 Android App 完成首次权限和扫描。
- [ ] 微信正式版/体验版完成最小烟测。
- [ ] ESP32 固件与客户端发布说明互相引用正确版本。

## 阻断规则

以下任一项存在时不得宣称“完整可用”：

- 扫描、连接、Read/Write/Notify 任一 Must 流程无 E5 证据。
- Android 或微信出现崩溃、白屏、死路、假成功或敏感数据泄露。
- OTA 未收到设备 success 就显示完成，或重启后版本不一致。
- 广播状态与第二设备观察结果不一致。
- ESP32 固件只能在某台开发机的固定串口/私有配置构建。
- 落地页宣称某平台支持，但平台矩阵或测试结果为 Degraded/Blocked。
