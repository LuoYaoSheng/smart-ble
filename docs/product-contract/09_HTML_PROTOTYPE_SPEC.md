# HTML 可交互原型规范

## 定位

HTML 原型是 UniApp 产品交互母版，用来先验证功能、页面、状态和平台差异。它不是生产代码，也不直接调用 BLE。页面实现不得凭空新增原型和契约中不存在的主流程。

## 文件结构

实施阶段创建：

```text
docs/prototypes/uniapp-reference/
├── index.html
├── prototype.css
├── prototype.js
├── prototype-data.js
└── README.md
```

不继续扩展旧的单文件 `unified-device-discovery.html`；旧原型保留为历史证据，新目录成为唯一交互原型。

## 顶层控制

原型工具栏固定提供：

- 平台：微信 / Android / iOS / H5
- 页面：PAGE-001~010
- 场景：正常 / 空 / 加载 / 失败 / 权限拒绝 / 断线 / 不支持
- 数据集：无设备 / 普通设备 / ESP32 / Smart HID / 多设备
- 重置：恢复当前平台默认状态

平台切换保持同一业务对象和页面编号，只改变平台允许的导航、字段、权限和能力说明。

## 平台视图

### 微信

- 手机尺寸和微信小程序导航。
- 四 Tab；页面标题、分享和扫码按微信语义。
- 扫描和广播展示 central/peripheral 模式交接。
- 开发者工具限制与真机能力不得混淆。

### Android App

- Android 手机尺寸、状态栏和返回行为。
- 权限弹窗、永久拒绝后的设置入口、文件 OTA 和原生 Peripheral 设置。
- 后台/前台、应用恢复和系统蓝牙关闭场景。

### iOS App

- 使用相同页面契约，采用 iOS 导航与权限文案。
- 标记为后续验收，不展示未经验证的成功能力。

### H5

- 页面、落地页和文档入口可用。
- 扫描与广播明确 Unsupported，提供打开微信/下载 App 的行动。

## 必须实现的交互

| 原型流程 | 必须可点击结果 |
|---|---|
| FLOW-001 | 开始→扫描中→结果/无结果/失败→重试 |
| FLOW-002 | 设备卡片→广播详情→复制→关闭 |
| FLOW-003 | 连接→服务树→Read/Write/Notify→日志 |
| FLOW-004 | 两台设备→已连接→单独/全部断开 |
| FLOW-005 | ESP32 四种 LED 命令和权限特征值 |
| FLOW-006 | payload 校验→广播中→停止/失败 |
| FLOW-007 | OTA 选择→Ready→进度→成功/取消/失败 |
| FLOW-008 | Smart HID 连接→表单→扫码→状态→详情 |
| FLOW-009 | 历史→详情→诊断/重配→返回 |
| FLOW-010 | 关于→版本→落地页/文档/开源链接 |

## 视觉规则

- 复用当前 UniApp `--ble-*` 设计 token 和真实品牌资源。
- 不制作新的视觉方向；先解决信息层级、状态和交互。
- 同一控件在不同平台保持语义，不强制相同组件外观。
- 禁止 Emoji 代替正式图标，禁止用装饰图掩盖缺失状态。
- 手机视图主操作无需滚动即可看到；桌面预览只作为开发工具外壳。

## 原型数据模型

`prototype-data.js` 使用与产品契约一致的稳定数据：

```js
{
  platform,
  pageId,
  scenario,
  adapter,
  scanSession,
  devices,
  sessions,
  selectedDevice,
  services,
  logs,
  broadcast,
  ota,
  smartHid
}
```

数据集不得包含真实 Wi-Fi 密码、token 或个人设备标识。

## 验收

- 10 个页面均可由页面选择器进入。
- FLOW-001~010 无死路，每个返回动作到达正确页面。
- 关键页面至少有正常、空、失败和平台差异状态。
- 微信/Android 的 Must 能力可走完整模拟流程。
- H5 的 BLE 控件不会模拟成功。
- 自动化检查页面、按钮、状态和平台矩阵数量。
- 原型截图通过移动视口视觉检查后，才允许同步代码。
