## 1. S2 配网（配对码：扫码为主，粘贴/手输兜底 · 2026-09-03 用户修正）

```
P002 configure → 「扫描 ControlHub 配对码」（与基准同口径 · F020）
   ├─ 主路径：摄像头扫码 sheet（取景器 + 扫描线）→ 识别 shid://pair 二维码
   │     → 自动回填 ControlHub 地址 + 配对令牌（token 已获取 → bigact got 态）
   └─ 兜底：「无法扫码？粘贴 / 手输配对码」→ sheet 输入 shid://pair?hub=…&t=…
         → 解析（正则 hub= / t=，纯前端）→ 回填同上
   → 下发 → 基线四行进度 → READY → P003（同基准）
扫码取消 / 兜底解析失败 → 表单不清空；兜底无令牌 → toast「未识别配对码（需包含 t=… 令牌）」。
```

## 2. S1 / S4 / S5（选型待定的部分）

扫描列表、广播启停、OTA 事务的**产品流程同基准**；底层 BLE 经原生层（CoreBluetooth/WinRT/BlueZ 或 btleplug【待验证：D2 spike】）。spike 结论出来前，流程图按基准口径评审，不预判实现。

> **操作系统维度（2026-09-03 用户走查追加）**：原生层按宿主 OS 区分——macOS CoreBluetooth / Windows WinRT / Linux BlueZ（与 11_ecosystem 矩阵 WIN/MAC/LINUX 行一致）。切换入口在 P009（applyOS 联动窗口 chrome 三形态 / 环境信息 / P008 徽标与原生层提示 / 评审栏生态矩阵卡）；Linux 广播外围受 BlueZ/内核权限影响【待验证】，启动日志显式提示。**产品流程不随 OS 变化**。

## 3. 生命周期（BR-06 桌面表达）

```
常驻运行 ←→ 窗口关闭 → 退出确认
   ├─ 继续使用（默认语义：常驻）
   └─ 退出 → 断开 BLE 会话（活动连接 disconnect / 广播停止）→ 退出
```

## 4. 出口流程

外链→系统浏览器；分享→导出文本（复制为主，文件候选拦截）；日志导出→复制（文件流候选拦截）。
