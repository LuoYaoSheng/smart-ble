## 1. 产品定位

> **面向 UniApp、微信小程序与 ESP32 协同验证的 BLE 调试工具。**

产品模型：**通用 BLE Inspector（检查器）+ 可扩展设备 Profile（档案）系统**。核心不是某一个硬件，而是提供从发现 BLE 设备、查看广播、连接 GATT、调试通信、升级固件，到接入第一方硬件 Profile（Smart HID 配网）的完整工具链。

**Profile 扩展原则（2026-09-03 用户走查确立）**：特殊设备（Smart HID 等 Profile 设备）是标准 BLE 设备的**扩展**，而非替代——在任何平台、任何入口，特殊设备必须保留标准设备的全部能力（发现/广播数据/连接/GATT 调试/日志），Profile 能力（配网/诊断）在其上叠加。基线落地：`prototype/v1-new/components/components.js` devCard（v1.0.1，SHID 卡 = 配置入口 + 标准连接入口）。

## 2. 产品边界（明确不做）

- 不做登录 / 会员 / License / 支付 / 订单 / 商业设备管理
- 不做 HID 实时键鼠控制（属 ControlHub→MQTT 链路，小程序只负责配网与诊断）
- 不做云同步 / 远程设备管理
- 不做 H5 端支持

## 3. 核心价值（5 条）

1. **口袋里的 BLE 调试台**：微信里完成扫描→筛选→广播分析→GATT 读写监听→日志导出闭环。
2. **看得见的广播**：手机可变 BLE 外设发射广播（微信/App 双路径），31 字节预算实时核算，广播结构可教学、可验证。
3. **第一方硬件的配网入口**：Smart HID 扫码配对、三步向导、状态机全程可视、错误码给恢复动作。
4. **可扩展的 Profile 架构**：新设备家族以注册表接入（UUID/前缀匹配→专属路由与动作），通用调试能力全家族复用。
5. **诚实的安全约定**：Wi-Fi 密码与配对凭据仅内存、不落日志不落盘；日志全局脱敏。（2026-09-02 决策后为零本地持久化形态。）

## 4. 用户角色

| 角色 | 特征 | 核心使用 |
|---|---|---|
| U1 BLE 固件开发者 | 写 ESP32/Nordic 固件，反复验证广播与 GATT | 扫描/广播查看/读写字符/notify（F001-F012） |
| U2 硬件工程师 | 自研 Smart HID 类设备，交付配网体验 | 配网全流程 + 现场诊断（F018-F024） |
| U3 测试/售后人员 | 现场验证设备状态 | 扫描筛选定位、广播对照源、五项诊断 |
| U4 BLE 学习者/教学 | 理解广播包结构与 31 字节限制 | 广播页实时核算、广播弹窗、UUID 标准名 |
| U5 自研硬件接入者 | 把自己设备接入这套工具 | 按 Profile 契约注册（代码层） |
| U6 同生态普通用户 | ~~发现同开发者小程序~~ | ~~推广卡跳转（F028）~~（2026-09-10 移除） |

主用户 = **专业人士（U1–U3）**，工具属性强，无娱乐化设计；UI 语言全中文。

## 5. 使用场景（摘要，详版 PRD §3）

| 场景 | 一句话 |
|---|---|
| S1 调试自研 BLE 设备 | 扫描 5s→看广播→连 GATT→读/写/监听→导出日志（最高频） |
| S2 Smart HID 首次配网 | SHID 卡→三步向导→扫码→下发→四行进度→READY→查看设备 |
| S3 Smart HID 故障排查 | 设备进恢复模式→重配入口→配网报错→运行诊断→五项定位（2026-09-02 后不经历史面板） |
| S4 广播验证/教学 | 广播页填参数→31B 实时核算→发射→观察端验证 |
| S5 固件升级（受限） | OTA 设备「固件更新」→校验→传输→版本回读（当前 BLOCKED） |
| S6 多设备管理 | 已连接页单台/批量断开（失败清单） |
