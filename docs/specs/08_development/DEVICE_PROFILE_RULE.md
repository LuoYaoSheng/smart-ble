# DEVICE_PROFILE_RULE —— Device / Profile 开发规则（四条铁律）

## 0. 关系模型总览

```
        ┌─────────────────────────────────────────────────┐
        │  Device（基础实体 · 基座）                        │
        │  发现 → 广播查看 → 连接 → GATT 调试 → 日志 → 断开   │  ← 旅程 S1（最高频，无 Profile 参与）
        └────────────────────△────────────────────────────┘
                             │ 只叠加，不替换（识别注入：徽章/专属动作/专属路由）
        ┌────────────────────┴────────────────────────────┐
        │  Profile（扩展能力 · 第二轴）                      │
        │  Smart HID：配网向导 / 身份验证 / 诊断 / 会话快照   │  ← 旅程 S2/S3（Profile 专属事务）
        └─────────────────────────────────────────────────┘
```

产品模型两轴（PRODUCT_MODEL §1）：**通用 BLE Inspector（检查器）为主体 + 可扩展设备 Profile（档案）系统为第二轴**。连接与配网是**两条独立旅程、两个能力域**；下述四条规则是这一模型在开发层的强制形态。

---

## DR-1 Device 是基础实体

**规则**：设备（Device）是全部通用能力的宿主与第一等实体——扫描发现、广播数据查看、连接、GATT 调试、通信日志都直接作用于 Device，**不依赖任何 Profile 存在**。无 Profile 的普通设备是产品的默认对象与最高频场景。

| 依据 | 内容 |
|---|---|
| PRODUCT_MODEL §1/§3 | 通用 BLE Inspector 为主体；核心价值 1「口袋里的 BLE 调试台」全链路以设备为对象 |
| USER_FLOW S1 | 最高频旅程：扫描 → 广播弹窗 → 普通卡「连接」→ P006 GATT → 日志 → 断开，**全程无 Profile 参与** |
| FEATURE_MAP §1/§4 | 扫描/连接/GATT/读写/监听/日志属通用能力域；Profile 配网域单列 |
| ALIGNMENT_NOTES §3 | 生态 BLE-001～012（检测/扫描/连接/GATT/读写/Notify/广播/日志/OTA）为独立通用全集，BLE-013 Profile 单列 |

**开发落点**：设备列表、连接会话、GATT 面板的数据结构与流程以 Device 为中心建模；Profile 匹配结果（profileMatch / profileId）只能是 Device 上的**可空注记字段**，不得成为任何通用路径的前置条件或硬依赖。

**违例判定**：出现「设备须匹配到 Profile 才能连接 / 查看广播 / 进 GATT」的任何实现；通用页面代码对 Profile 模块形成硬 import 依赖。

## DR-2 Profile 是扩展能力

**规则**：Profile 是叠加在 Device 基座上的**识别与专属动作扩展**（识别 → 徽章 / 专属动作 / 专属路由），**只叠加、不替换**——Profile 设备保留标准设备全部能力，通用调试能力全家族复用。

| 依据 | 内容 |
|---|---|
| PRODUCT_MODEL §1 | Profile 扩展原则（2026-09-03 用户走查确立）：「特殊设备是标准 BLE 设备的**扩展**，而非替代……Profile 能力（配网/诊断）在其上叠加」 |
| PRODUCT_MODEL §3-4 | 核心价值 4：新设备家族以注册表接入（UUID/前缀匹配 → 专属路由与动作）；U5 自研硬件接入者按契约**代码层注册** |
| DEVICE_PROFILE_SPEC §2/§4 | 匹配规则 UUID=STRONG 优先于前缀=WEAK；PR-1 只叠加不替换 / PR-4 配网域**复用** GATT 连接·写入·notify 基础设施 / PR-6 识别不得影响无 Profile 设备 |
| ALIGNMENT_NOTES §3 | BLE-013 与 Profile 扩展原则同构；生态矩阵 §13 `registerProfile` / `matchProfile` 接口同构（08 阶段定型）；「自定义页面/协议/解析」为生态全集表述，**不反向扩 v1 范围** |

**开发落点**：Profile 经注册表注册（服务 UUID / 名称前缀 + 专属动作与路由）；匹配结果只注入**展示**（徽章、专属按钮）与**路由分流**（P007 点卡按 profileId 分流，无 Profile → P006）；Profile 专属事务构建在通用 ble-runtime 之上，不得另起连接栈。

**违例判定**：Profile 分支隐藏 / 禁用 / 替换标准能力入口；识别逻辑改变无匹配设备的通用路径（显示名 fallback「未命名 BLE · ID后四位」不受匹配影响，R05）；为绕开注册表在通用代码中硬编码某设备家族分支。

## DR-3 配网不是连接的必然流程

**规则**：**连接（F006 → P006 GATT 调试）与配网（S2 旅程 → P002 向导）是两条独立旅程**。连接不需要、不触发、不等待任何配网步骤；配网是 Smart HID Profile 的专属事务，其入口是用户显式选择。任何设备（含 Smart HID）都可以**只连接、不配网**。

| 依据 | 内容 |
|---|---|
| USER_FLOW S1 vs S2 | S1 连接路径「普通卡『连接』→ P006（F006）」**无配网步骤**；S2 配网为独立旅程（SHID 卡「配置」动作进入向导，含自动连接+身份验证） |
| PRODUCT_MODEL §5 | 场景表 S1（调试）/ S2（配网）/ S3（排查）分列——配网是场景级选择，非连接的中间步骤 |
| DEVICE_PROFILE_SPEC §3.1/§3.5 | `verifyDeviceInfo` 身份验证只发生在配网向导入口（连接后、进入 S2 时）；会话计数口径：配网会话**不占用** P007 通用连接列表（两种会话分账，session.provisioning 互斥） |
| PAGE_SPEC §1/§7 | P001 连接动作直达 P006；P007 为通用调试会话页 |

**开发落点**：连接路径（P001「连接」→ P006）不得插入配网前置步骤、引导弹窗或状态等待；身份验证（verifyDeviceInfo）只挂在配网向导入口，不在通用连接路径执行；配网会话与通用连接会话分开记账（互斥标志 + 计数口径：P001「已连接」= 通用连接数 + SHID 配网会话在线）。

**违例判定**：连接成功后强制弹出配网引导；连接流程内嵌配网等待/状态轮询；把配网会话塞入通用已连接列表（或反之）；未走「配置」入口却在连接路径触发配网事务。

## DR-4 Smart HID 必须同时支持普通连接入口与 Profile 专属入口

**规则**：Smart HID 设备卡（及一切可达 Profile 设备的入口）必须**并存**两个入口：① 普通连接入口——与普通设备卡同路径的「连接」（→ P006 GATT 调试）；② Profile 专属入口——「配置 Smart HID」（→ P002 配网向导）。**两者并存，不可二选一、不可互斥隐藏**。

| 依据 | 内容 |
|---|---|
| PRODUCT_MODEL §1/§6 | Profile 扩展原则基线落地句：devCard v1.0.1「SHID 卡 = 配置入口 + 标准连接入口」；决策记录 2026-09-03 ①（用户走查确立） |
| USER_FLOW S1/S2 | 两条旅程各有入口：S1 由「连接」进入，S2 由「配置 Smart HID」进入——双入口是旅程结构在卡片层的投射 |
| DEVICE_PROFILE_SPEC §3.2/PR-2 | 入口表前两行：「P001 SHID 卡『配置 Smart HID』→ P002」与「P001 SHID 卡『连接』（标准能力）→ P006，与普通卡一致」；PR-2 为基线落地形态 |
| ALIGNMENT_NOTES §3 | BLE-013 行：Profile 扩展原则 2026-09-03 收口（特殊设备 = 标准设备的扩展），Smart HID = 首个内置 Profile |
| 10_platform §6 修正① | 平台层同口径修正（三平台内核重同步 + Web W2） |

**开发落点**：SHID 卡双按钮（Profile 主入口 primary + 标准连接入口，基准原型 devCard v1.0.1 形态）；SHID 的「连接」与普通设备连接走**同一 handler 与路径**；P007 点卡按 profileId 分流到 Profile 路由的同时，P006 通用调试入口必须保持可达（P003「高级 BLE 调试」同理）。

**违例判定**：出现「有 Profile 动作就不渲染连接按钮」的二选一实现（v1.0.0 devCard 真实教训：isShid 时连接入口被配置入口替代，特殊设备丢失标准 GATT 链路——2026-09-03 用户走查判违例并修正为双入口）；SHID 连接走与普通设备不同的私有路径；Profile 分流后 P006 不可达。
