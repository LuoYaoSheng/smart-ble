---

## 1. 审查方法

清点全产品权限触点（功能号 / 页面 / 平台 / 触发时机 / 拒绝处理），核对三点：①触发时机是否符合「用户触发」原则；②拒绝路径是否闭环（提示 + 去设置 + 可重试）；③权限异常态是否进入六态验收。

## 2. 结论摘要

| 维度 | 结论 |
|---|---|
| 权限触点 | 3 个功能域 4 个触点：扫描（F002，微信）、扫码（F020，配网内）、广播（F015，Android）、系统蓝牙开关（全平台前置） |
| 触发时机 | 全部为**用户动作触发**（点「开始扫描」/ 调起扫码 / 点「开始广播」），无启动时申请——符合评审规范 §12 ✅ |
| 拒绝闭环 | 四触点均有分类提示 + 去设置 / 重试出口，无死路 ✅ |
| 权限异常态 | 已入 PAGE_SPEC §11 矩阵与 v1-new 场景库（权限类覆盖蓝牙未开 / 扫码 / 广播权限，README 验收项 5）✅ |
| 架构收口 | 微信权限检查收敛于单服务（services/scan-permission.js，全项目唯一直调 wx.* 的服务，PAGE_SPEC §0.3）——重开发保持该收口 |

## 3. 权限触点清单

| 触点 | 平台 | 触发时机 | 拒绝 / 缺失处理 | 源 |
|---|---|---|---|---|
| 蓝牙 + 定位授权（扫描前置） | 微信 | 点「开始扫描」时前置检查 | 横幅 reason 分类（bluetooth_permission_denied 等）+ 引导设置；返回后可重扫 | F002；PAGE_SPEC §1 |
| 扫码权限（相机） | 微信 / APP | 配网页点「扫描配对码」调起扫码 | 取消 / 权限 / 失败三分类提示，可重扫（取消不算错误） | F020；PAGE_SPEC §2 |
| FINE_LOCATION（SDK≥31 追加 ADVERTISE / CONNECT） | Android | 点「开始广播」时逐项请求 | modal「去设置」跳应用详情；弹窗拒绝→汇总缺失清单 + 去设置 | F015 / R23；PAGE_SPEC §8 |
| 系统蓝牙开关 | 全平台 | 扫描初始化 / 广播启动前置 | 微信 10001 弹窗引导；Android modal + Intent 直达设置 | PAGE_SPEC §1 / §8 |

## 4. 平台权限模型差异（收口自 10_platform §4）

| 平台 | 权限模型 | 备注 |
|---|---|---|
| 微信小程序 | 授权弹窗 + 去设置（F002 现状） | 权限检查单服务收口 |
| App·Android | 运行时权限 + 清单引导（F015 现状） | SDK≥31 权限分组 |
| Web | chooser 选择即授权 + HTTPS 安全上下文 | 无传统权限弹窗（若做子集版） |
| Desktop | 系统蓝牙权限 / 首次配对 | 平台扩展期核实（macOS / Windows / Linux 各异） |

权限维度**无缺口**：本产品无相机相册 / 后台定位 / 推送等重权限，触点少而清晰，全部用户触发、闭环完整。
