## 1. 问题与依据

### 1.1 故障机理

组件定义（`v1-new/components/components.js:44-48`，四平台壳同路径同内容）：

```js
empty({ill='box', title, desc='', act=null}){
  return `<div class="empty"><div class="ill">${C.ILL[ill]||C.ILL.box}</div>
    <div class="t">${title}</div>${desc?`<div class="d">${desc}</div>`:''}
    ${act?C.btn({label:act.label,tone:'soft',icon:act.icon||'',act:act.act}) : C.btn({label:'',tone:'soft'})}</div>`;
}
```

调用侧（修复前，以 p001 为例）：`C.empty('link','当前没有匹配设备','调整筛选条件试试',null)` —— 首参为字符串，对象解构得到全部 `undefined`：

| 解构字段 | 位置参数下的值 | 渲染后果 |
|---|---|---|
| `ill` | `undefined` → 默认 `'box'` | radar/link/doc 三幅插图选择失效（TOKEN §7 作废） |
| `title` | `undefined`（无默认值） | 主文案渲染字面量 `undefined` |
| `desc` | `undefined` → 默认 `''` | 说明文案丢失 |
| `act` | `undefined` → 默认 `null` | 「开始扫描」「去扫描」CTA 按钮丢失 |

### 1.2 规范依据

- **COMPONENT.md §B6**：空态结构 = 插图（§7 4 幅）+ 主文案（--fs-h1）+ 说明（--fs-body --c-mut）+ 可选 action（soft 按钮）；双空态规范（P001 两套 / P007 两套 / P010 三套）。
- **审计 A-01 原文**（HTML_DEVELOPMENT_READINESS_AUDIT.md:41）指认修复方案二选一，本轮采用 **①调用点改为对象参数**（审计推荐：与 `web.js:263` 现行正确写法一致）；方案②（组件双签名兼容）被任务要求 1 明确排除——保留组件对象参数设计，不修改组件 API。
- **审计同时点名 QA 盲区**：v1 冒烟 26/26 声称通过与首屏空态损坏矛盾，说明断言未覆盖空态文案——本轮 32 项空态断言（含 CTA 存在性、插图语义、文案全等）即为该盲区的整改落地（脚本固化建议见 §5.2）。
