# 11 · 产品优化建议

> 基于 06-10 五份问题清单的产品层建议。按「投入产出比」排序，分四个方向。所有建议均不动业务主链路（§32 审计边界：本文件只是建议，修复实施见 12_修复路线图）。

---

## 方向一 · 把「沉默事件」说出来（低成本高感知，6 处 P2 的共同解法）

| 建议 | 对应问题 | 预期效果 |
|---|---|---|
| 1. 建立统一「事件播报」约定：扫描完成、权限拒绝、连接断开、停止失败等终端事件必须有一个 toast/横幅/状态条载体 | 06-F01/F05/F06、09-A01/A03、10 §1 缺失层 | 一处约定解决 5 处 P2，用户从「界面静止」变为「始终知道发生了什么」 |
| 2. 诊断页尾部加动作区（重试连接 / 重新配网 / 返回设备） | 06-F02、10 诊断后 | 诊断从报告变工具，闭环率 +1 |
| 3. P003 假按钮二选一：真实现（携 deviceId 跳 P006）或删除 | 08/FC-01 | 消除最刺眼的信任损耗点 |

## 方向二 · 收口架构（治本，两处双轨的根因）

| 建议 | 对应问题 | 说明 |
|---|---|---|
| 4. 广播页适配器调用收进 ble-runtime：runtime 增加 mode 维度（central/peripheral）与 open 幂等重入，广播页改为 `runtime.ensureAdapterReady('peripheral')` | 09-M01、08 §3 P1 风险 | 先真机验证冲突是否复现；无论结果如何，收口本身消除「页面层直调」这个质量洼地（09 §1 已证明洼地规律） |
| 5. 恢复词汇表合并：`workflow.smartHidRecoveryAction` 与 composable `recoveryFor` 二选一作为单一来源 | 09-S04 | 防未来改一处漏一处 |
| 6. 设备编号统一：对用户只暴露一个 ID（建议 device_id），`SHID-` 广播名仅作识别层内部概念 | 09-S01 | 用户心智从两套编号变一套 |

## 方向三 · 诚实与自描述（品牌资产）

| 建议 | 对应问题 | 说明 |
|---|---|---|
| 7. PRODUCT_FEATURES 加入「Smart HID 配网」，summary 改为直说核心场景（如「为 Smart HID 设备完成扫码配网，兼作全功能 BLE 调试器」） | 06-F13 | 关于页是唯一自述位，当前传达不出差异化 |
| 8. 清理「装饰性状态」：静态「连接稳定」改为真实 RSSI 派生或删除；协议 chip 去 success 色；更新定位权限文案 | 07-D03/D04/D10 | 延续产品已有的诚实基调（诚实降级做得好，装饰性状态是唯一的倒挂） |
| 9. P001 文案去重（用户点名项）：「附近设备」「已连接」各保留一处 | 07-D01 | 用户直接点名，优先级事实上的 P1 |

## 方向四 · 面向下一版本的产品演进（backlog，非本期缺陷）

| 建议 | 动机 | 量级 |
|---|---|---|
| 10. 固件物理 RECOVERY 触发（按键/长按组合） | 重配网 5 分钟等待是当前最长的用户痛路径（04/S5），小程序端已无优化空间，瓶颈在固件 | 跨端，中 |
| 11. 协议 V2：Wi-Fi 扫描特征值（设备侧回传 AP 列表，用户选择而非手输 SSID） | 消除 SSID 手输错误这一最高频配网失败源；需固件+小程序同步升级 | 跨端，大 |
| 12. 配网 V2 流程提案（用户已提出方向，见会话记录） | 用户对三层凭据模型有产品级直觉，值得立项讨论 | 需先做方案对比 |
| 13. 历史设备 hardware 元数据展示 + 溢出提示 | 存而不用的小浪费（06-F14/F17） | 小 |
| 14. 版本页样式并入 design token 体系 | 07-D17，最后一处视觉孤岛 | 小 |

## 优先级速览

```
立即（发版前）：#3 假按钮、#1 事件播报约定（含相机权限）
尽快（下个迭代）：#2 诊断出口、#4 广播收口（先真机验证）、#9 文案去重
规划（下个版本）：#5 #6 #7 #8 + backlog #10~14
```
