> 审计方法：对九页逐一构建「状态设计矩阵」（空态 / 加载态 / 成功态 / 失败态 / 权限态 / 中间态），找**缺失的格子**。判定视角：异常发生时，用户看到的是「解释」还是「静止/误导」。

## 3. 结论

**异常处理的成熟度呈三层分布**：

1. **优秀层（无需动）**：蓝牙开关、连接超时、固件 error 分流、广播 10008 降级、外跳失败兜底——这些覆盖了最高频的异常，且提示均为中文可行动文案。
2. **缺失层（本审计的主要产出，5 处 P2）**：相机权限拒绝、扫描完成反馈、provision 断开中间态、诊断后出口、（潜在）双模冲突。**共同特征：都是「事件已经发生、代码已捕获，但 UI 不表达」**——不是检测能力缺失，是表达层缺失，修复成本低。
3. **打磨层（P3/P4）**：文案时效性、截断提示、溢出提示、空态图语义。

一句话总结：**这个产品「检测得到异常」的能力已经建好（runtime 归一化 + 状态机），欠的是「把检测到的异常说给用户听」的最后一跳。**
