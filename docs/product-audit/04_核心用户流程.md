## F01 首次扫描与通用 GATT：PARTIAL

1. P001 读适配器状态 → 开始扫描 → 授权 → runtime 发现回调 → 列表。
2. 连接 → P005 解析路由 → connect/discover → 读写通知。

**第一断点（仍成立）：** `services.length > 0` 才渲染 service-panel → 加载/空/失败无主 UI。

假设修复后：仍需验自动重连只写日志、无手动重试控件。

---

## F02 Smart HID 配网与再入：PARTIAL → 再入已改善

1. P001 Profile 识别 → P002 连接/表单/扫码/写 candidate → Status ready → 写历史 → P003。
2. 重启后：P001 历史「查看」→ P003；「移除」→ `removeKnownDevice`。

**原第一断点（无 UI 读 knownDevices）已消除。**

**当前第一断点：** 配网等待无取消/离页确认；扫码 `fail` 空处理（P2）。

假设修复后：历史列表仍无直达重配/诊断（需经 P003）；无过期策略。

---

## F03 广播：PARTIAL → 静默失败已修

1. 表单 → `validateAppBroadcastStart`（App）→ 插件/微信 server → 状态+日志。

**原第一断点（早退无反馈 / 空 catch）已消除。**

**当前第一断点：** 原生插件参数形状与真机能力未验；devtools 探测仍有空 catch（非启动路径）。

---

## F04 OTA：FAIL（假完成）→ PARTIAL（诚实等待）

1. 选文件 → 写 chunk → **等待 JSON `{status:success}`** → 成功 UI；超时/error/取消 → 失败。

**原第一断点（写完即 onSuccess）已消除。**

**当前第一断点：** 若固件不实现 status（审计与 Phase1 决策已注明），用户只会超时失败；无 CRC/版本回读；控制命令未下发（固件未实现）。

评级：**客户端正确性 PASS；端到端产品完成度仍 PARTIAL/待真机。**

## 设备对象生命周期（Smart HID）

| 环节 | 入口 | 实现 | 结论 |
|---|---|---|---|
| 创建 | P002 ready → `commitKnownDevice` | 非敏感字段入 Storage | PASS |
| 查看 | P001 历史 / P003 | 已接通 | PASS（2026-08-29） |
| 编辑（重配） | P003 → P002 | 有跳转 | PASS，列表无快捷入口 |
| 使用（诊断/GATT） | P003 → P004/P005 | 有跳转 | PASS，待真机 |
| 状态变化 | Status notify | 配网期有；详情页非实时 | PARTIAL |
| 删除 | P001 移除 | `removeKnownDevice` | PASS |
| 再次查看 | 删除后历史消失 | 空态合理 | PASS |
| 过期/冲突 | — | 无策略 | 遗漏（P3/P4） |

通用 GATT 会话：创建于连接，随进程/断开销毁，无持久对象——符合设计。
