## V1 · 适配器双模冲突验证（P1 定级依据）

**背景**：广播页直调 `wx.openBluetoothAdapter({mode:'peripheral'})`（broadcast/index.vue:214/:554）绕过 runtime；runtime 的 `adapterReady` 标志不区分模式；全应用无 `closeBluetoothAdapter`。需验证 central（扫描/连接）与 peripheral（广播）混用是否互踩。

**准备**：一台已配网的 Smart HID 设备（或任一 BLE 设备）用于扫描验证；微信开发者工具扫码预览进入小程序。

| 用例 | 操作步骤 | 轮次 | 每轮记录 |
|---|---|---|---|
| T1 | 广播页「开始广播」→「停止广播」→ 切设备 Tab「开始扫描」 | ×10 | 扫描是否出结果；errCode/errMsg（如有） |
| T2 | 广播页「开始广播」→ **保持广播中** → 切设备 Tab「开始扫描」 | ×10 | 同上；另记广播是否仍正常 |
| T3 | 设备 Tab 先扫到设备 → 不停扫描 → 切广播页「开始广播」 | ×10 | 广播是否成功；返回设备页扫描是否还出结果 |
| T4 | 广播中 → 设备 Tab 扫描并点击某设备「连接」 | ×5 | 连接是否成功；错误提示内容 |
| T5 | 开广播 → 直接杀掉小程序 → 冷启动 → 设备 Tab「开始扫描」 | ×5 | 扫描是否出结果（验证无 close 的残留态） |

**判定标准**：
- 任一轮出现「扫描无结果 + 误导性报错（如 10001 未初始化 / 10008 已连接类）」或「广播静默失效」→ **P1 实锤**，记录精确操作序列与 errMsg，转 R1（runtime mode 维度收口）。
- 5 组全部干净 → 降级 P3 架构债，R14（仍建议收口统一调用层）。

## R3 验收 · 扫码相机权限分流（已修复，待真机过单）

修复内容：`services/smart-hid/scan-code-feedback.js` 的 `describeScanCodeFailure` 按 errMsg 三路分流（取消 → 轻量 toast；权限拒绝 → 引导弹窗；其他失败 → 失败弹窗），由配网 composable 接线。

| # | 步骤 | 预期 |
|---|---|---|

| R3-3 | 点「扫码」→ 相机拉起后手动返回（取消） | 轻量 toast「已取消扫码」，无阻断性弹窗 |
| R3-4 | 扫一张非配对码的普通二维码 | 「无法识别配对码」弹窗（原有行为不回归） |
| R3-5 | 配网失败 → 恢复动作「重新扫码」路径 | 分流逻辑同样生效（同走 scanControlHubQr） |
